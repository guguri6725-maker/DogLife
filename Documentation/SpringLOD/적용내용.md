# Spring 거리별 LOD

Spring 5개 방의 고밀도 식생(꽃, 수풀, 나무, 뿌리, 화단)에 3단계 LOD를 적용했습니다. 큰 결합 메시를 로컬 X/Z 12 단위 구역으로 나누어 구역별로 전환합니다. 원본 FBX와 충돌 메시, 문, NavMesh는 변경하지 않았습니다. 석조 Structure는 감소 시 모서리 손상이 보여 제외했습니다.

- LOD0: 원본 삼각형/UV/법선 유지. 원본 렌더러는 비활성화하고 원본 구역 메시가 대신 그립니다.
- LOD1: 대상 메시 삼각형 약 50%.
- LOD2: 대상 메시 삼각형 약 20%. 최종 단계 임계값 0으로 거리 때문에 통째로 숨기지 않습니다.
- Unity LODGroup 화면 상대 크기 임계값: 0.65 / 0.30 / 0. 현재 프로젝트 lodBias=2는 유지했습니다. 고정 미터 거리가 아니라 구역 크기, 카메라 FOV/거리, 품질 설정에 따라 전환합니다.
- 충돌은 원래 메시를 사용합니다. 보행/문/방 스트리밍 로직은 변경하지 않았습니다.
- 재사용 메시 157개 × 3단계, 배치된 LODGroup 213개입니다. LOD 데이터를 추가하므로 메모리와 저장 용량은 늘어납니다. 구역 분할로 렌더러 수도 늘어납니다. FPS 개선 폭은 실제 게임 프로파일링이 필요합니다.

## 삼각형 수

각 방의 활성화된 고정 메시를 포함하며, 모든 구역이 같은 LOD 단계일 때의 합계입니다. 실제 화면은 거리별 단계가 혼합되고 카메라 컬링이 적용됩니다. 공통 씬/실행 중 생성되는 적은 제외합니다.

## 확인

- 전체 방 LODGroup의 메시 연결, 3단계 구성, 마지막 단계의 비컬링 설정 검사: 문제 0건.
- 대상별 원본 삼각형 수와 분할된 LOD0 삼각형 합계 일치.
- Room04_Synthesis 동일 카메라/조명에서 적용 전과 LOD0 비교: RGB 평균 픽셀 차이 0.
- 동일 시점 자동 전환 및 강제 원거리 단계의 스크린샷 확인. 강제 원거리 이미지는 가까운 물체까지 낮은 단계로 표시한 비교용이며 실제 자동 전환 화면과 다릅니다.
- 결과: `Counts.txt`, `Before.png`, `NearForced.png`, `Automatic.png`, `FarForced.png`.
- 게임 전체 주행, FPS/메모리 프로파일링은 수행하지 않았습니다.

## 생성 도구

`SpringLodBuilder.Export()` → Blender 백그라운드에서 `Tools/spring_lod.py` → `SpringLodBuilder.ImportAndApply()` 순서입니다. 중간 데이터는 `Library/SpringLODWorking`, 최종 메시 자산은 `Assets/MapDesigne/Spring/LOD`입니다. 이미 생성한 원본 구역의 중복 내보내기는 막고, 기존 LOD가 연결된 오브젝트에는 중복 연결하지 않습니다.
