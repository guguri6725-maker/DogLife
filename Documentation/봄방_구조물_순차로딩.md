# 봄 방 구조물 순차 로딩

## 적용 내용

- 봄 2~5번 방의 지형/장식 20개 묶음을 Assets/Resources/StreamedSpringGeometry 안의 프리팹으로 분리했습니다. 문과 외부 참조가 있는 오브젝트는 씬에 유지합니다.
- 방 씬은 구조물 경로를 보관하고, 실제 생성은 몬스터를 모두 처치한 뒤 프리팹별로 처리합니다. 구조물과 충돌 준비, 몬스터 생성 완료 후 문을 엽니다.
- 프리팹을 처음 읽을 때 내부 에셋 등록이 156~334ms까지 몰리는 문제가 검증 중 발견돼, 스테이지 시작 로딩에서 geometryWarmupPaths의 에셋 데이터를 준비하도록 보완했습니다. 이 단계는 방 인스턴스나 다음 방 몬스터를 생성하지 않습니다.
- 캐시 데이터는 스테이지 동안 유지합니다. 따라서 시작 로딩 시간과 메모리 사용이 증가합니다. 현재/다음 방 최대 2개 제한, 처치 후 생성 방식은 유지합니다.
- 분리한 구조물의 편집은 해당 프리팹에서 합니다. 원본 씬 백업은 Temp/BeforeGeometryExtraction에 있습니다(임시 폴더이므로 영구 버전 보관 용도는 아님).

## 확인

- 백업과 재구성한 4개 방의 메시 경로/이름, 재질, 월드 변환, 충돌 종류/메시/박스 크기·위치 비교: 95 / 121 / 139 / 182개 항목 모두 일치.
- 5개 방 연속 진행, 각 새 방의 몬스터 3마리 및 2종 이상, 준비 전 문 개방 0회, 최대 방 수 2 확인. 런타임 오류 없음.
- 최종 에디터 프로파일: 4개 처치 전환의 PlayerLoop 최대 8.47 / 3.32 / 2.84 / 4.47ms. 에디터 전체 Main Thread 최대 21.03 / 8.26 / 8.11 / 12.71ms.
- 프리팹 분리 직후 발견한 회귀를 수정한 결과이며, 원래 방식 대비 동일 캐시 상태의 성능 개선율을 뜻하지 않습니다. 에디터·캐시·몬스터 랜덤 조합에 따라 달라지고 실행 빌드 측정은 수행하지 않았습니다.
- Title 씬 및 기존 StageEnemy는 변경하지 않았습니다.
