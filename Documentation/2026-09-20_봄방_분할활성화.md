# 봄 방 구조물 분할 활성화

- 봄 방 5개 씬의 구조물 65개 묶음을 비활성 상태로 저장하고, 로딩 중 순차 활성화하도록 적용했습니다.
- ForestRoom의 activationBudgetMs 기본값은 2ms입니다. 개별 SetActive 호출을 중단하는 제한이 아니라, 처리 시간이 예산을 넘으면 다음 프레임으로 넘기는 기준입니다.
- 구조물과 충돌 준비, 몬스터 생성이 완료된 뒤 진행 문을 엽니다. 맵 배치와 충돌 형태는 유지합니다.
- 편집 시 ForestRoom 컴포넌트 메뉴의 ‘구조물 미리보기 (편집 전용)’으로 구조물을 볼 수 있습니다. 저장하면 분할 로딩을 위해 다시 비활성화됩니다.

## 검증

- 에디터 Play 모드에서 1~5번 방 전환 완료. 모든 방 구조물 활성화, 방마다 몬스터 3마리·2종 이상, 진입 후 이전 방 해제를 확인했습니다.
- Unity 콘솔 오류 없음. 테스트용 순간 이동 코드에서 kinematic Rigidbody의 속도를 설정한 경고가 발생했습니다. 테스트 코드는 프로젝트에 저장하지 않았습니다.
- 1→2번 방 단일 측정: LoadSceneOperation.CompleteAwakeSequence 약 10.97ms → 5.72ms. 충돌 메시 준비 약 4.12ms는 별도 코루틴 프레임으로 분리됐습니다.
- 이번 측정의 PlayerLoop 최대 7.28ms. 에디터 및 캐시 상태가 영향을 주는 단일 비교이므로 빌드 성능이나 모든 전환에서 같은 개선을 보장하지 않습니다. 큰 구조물 하나의 활성화 비용은 여전히 남습니다.

## 추가 개선: 충돌 준비 작업 분리

- 큰 구조물 하나의 SetActive에서 충돌 메시 준비가 여전히 4.6~6.9ms를 차지해, Physics.BakeMesh를 Unity Job 작업 스레드에서 먼저 실행하도록 변경했습니다. 완료 여부를 프레임마다 확인한 뒤 활성화합니다.
- 기존 메시, convex, cookingOptions를 그대로 사용합니다. 작업 도중 씬이 해제되면 작업 완료 후 메시가 해제되도록 처리했습니다.
- 봄 2~5번 방의 충돌용 FBX 12개만 Read/Write를 켰습니다. 작업 스레드에서 메시 데이터에 접근하기 위한 설정이며, 해당 충돌 메시의 CPU 메모리가 추가로 유지됩니다. 장식/몬스터 모델은 변경하지 않았습니다.
- maxGeometryGroupsPerFrame 기본값 1을 추가했습니다. SetActive 자체가 빨라도 이후 물리/렌더러 등록이 한 프레임에 겹치지 않도록 합니다.
- 도구 호출을 멈춘 재측정에서 4개 전환의 GameObject.Activate 최대는 각각 0.40 / 0.46 / 0.38 / 0.29ms, PlayerLoop 최대는 7.70 / 8.76 / 6.99 / 8.93ms였습니다. 메인 스레드 충돌 베이크의 0.2ms 이상 샘플은 나타나지 않았습니다.
- 5번 방까지 전환, 다음 방의 모든 구조물 활성화와 몬스터 3마리 소환, 이전 방 해제 확인. 콘솔 오류/경고 없음.
- 에디터를 포함한 Main Thread 전체 시간은 247~469ms의 스파이크가 남았습니다. PlayerLoop 수치만으로 전체 프레임 끊김이 해결됐다고 볼 수 없으며, 별도 실행 빌드에서 추가 검증이 필요합니다. 캐시와 에디터 상태의 영향도 있어 전후 수치를 보장 성능으로 사용하지 않습니다.

## 마지막 몬스터 처치 시점의 로딩 제거 실험 (되돌림)

사용자 요청으로 아래 사전 로딩 변경은 되돌렸습니다. 현재는 몬스터를 모두 처치한 뒤 다음 방을 생성하며, 진입 후 이전 방을 해제합니다. 앞서 적용한 분할 활성화와 작업 스레드 충돌 준비는 유지합니다. 아래는 실험 당시 기록입니다.

- preloadNextDuringCombat 기본값을 true로 추가했습니다. 시작 준비 중 첫 방과 다음 방을 완성하고, 이후 이전 방 해제가 끝나면 전투 중 다음 방을 준비합니다.
- 전투 클리어 시 다음 방이 준비돼 있으면 추가 로딩/몬스터 생성 없이 문을 엽니다. 준비 도중 빠르게 클리어하면 준비 완료까지 문을 닫아 둡니다.
- 별도의 roomPrepared 상태로 씬만 읽힌 상태와 구조물/몬스터까지 준비된 상태를 구분합니다. 준비 중에는 중복 로딩을 시작하지 않습니다.
- 방은 현재/다음 최대 2개입니다. 첫 시작의 준비 시간과 전투 중 메모리 사용은 늘어납니다. 로딩 비용 자체가 사라진 것은 아니므로 전투 중 사전 준비 구간에 지연이 발생할 가능성은 남습니다.
- Play 검증: 준비 완료 후 처치한 1/3/4번 방에서는 처치~문 열림 구간의 새 씬 로드 0회. 2번 방은 사전 준비 중 즉시 처치했으며, 준비 완료 후에만 문이 열렸습니다. 최대 방 수 2, 준비 전 문 열림 0회, 최종 방까지 진행 및 콘솔 오류/경고 없음.
